- 每个提供商文档遵循统一结构：标题 → 解锁的工具列表 → 环境变量 → 设置步骤 → 适用场景 → API 说明 → 定价表。
- 文档对变更采用“RFC 式”写法（如 `comfyui-adapter-plan.md`），先写动机与设计，再给出实现范围、开放问题与已解决项标记。
- PR 审查指南要求所有新工具必须继承 `BaseTool`、声明 `capability/provider/runtime/tier/stability` 等元数据，并通过 `tool_registry.discover()` 自动注册，禁止硬编码工具列表。
- 架构文档将知识分层表达为 Layer 1（工具/清单）→ Layer 2（skills）→ Layer 3（.agents/skills），并通过 `agent_skills[]` 字段建立跨层引用。
- 提供商与环境变量以表格形式集中列出，并在正文中用反引号标注精确的 `.env` 键名，避免自由文本歧义。
