- 对外部 HTTP/SDK 调用一律通过 `monkeypatch.setitem(sys.modules, 'requests', ...)` 或替换模块属性来注入 `FakeResponse`，避免任何真实网络请求。
- 需要进程间通信或临时文件的测试使用 `tmp_path` fixture 构造隔离目录，并用 `monkeypatch.setattr` 将目标模块的路径常量指向该临时路径。
- 行为测试按功能域组织为 `class TestCaseName:`，每个方法对应一个 happy-path / error-path / edge-case 场景，并使用 `assert result.success is True` 与字段断言组合验证。
- 契约类测试集中在 `contracts/`，通过 `isolated_tool_registry` fixture 注入独立的 `ToolRegistry` 单例，确保各测试之间不互相污染全局注册表。
- 需要真实 API 的用例统一标注 `@pytest.mark.live_api`，由根 `conftest.py` 的 `pytest_collection_modifyitems` 在默认模式下跳过，仅在启用 `OPENMONTAGE_ALLOW_NETWORK=1` 时执行。
- 基准场景通过 `BenchScenario` dataclass + `build_scenarios()` 工厂集中声明，并以 `tags` 字段支持 `--tag` 过滤，预期结果以 `expected_*` 字段声明并由 runner 自动比对。
