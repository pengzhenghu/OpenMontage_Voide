模块以扁平的 Python 包形式组织，按职责拆分为若干独立子模块：
- 配置与路径：`config_model.py` 基于 Pydantic 定义 `OpenMontageConfig`（LLM/预算/检查点策略/输出/路径），从 `config.yaml` 加载并合并环境变量；`paths.py` 暴露 `REPO_ROOT`、`PROJECTS_DIR` 作为全仓唯一路径来源；`env_loader.py` 负责 `.env` 加载。
- 流水线与样式：`pipeline_loader.py` 读取 `pipeline_defs/*.yaml`，用 `schemas/pipelines/pipeline_manifest.schema.json` 校验，并通过 `lru_cache` 缓存只读结果，暴露 stage 顺序、工具集合、扩展权限等查询函数；`playbook_generator.py` 在 `styles/` 下生成/保存符合 `schemas/styles/playbook.schema.json` 的样式剧本。
- 状态持久化：`checkpoint.py` 是编排器的核心——维护 `projects/<id>/checkpoint_<stage>.json` 布局，写入前执行阶段前置依赖检查、人类审批门控（从 manifest 的 `human_approval_default` 读取）、规范化的 artifact schema 校验，并将旧版本归档到 `history/`，同时维护 `decision_log.json`。
- 可观测性：`events.py` 以 append-only JSONL 记录每个项目的工具调用事件，供 Backlot 看板消费，所有 I/O 失败静默吞掉以保证生产可用性。
- 决策辅助：`scoring.py` 实现 ProviderScore / ProductionPathScore 加权打分引擎，结合关键词重叠、同义词簇、控制能力、成本、延迟、连续性等多维指标对 provider 排序；`delivery_promise.py` 将制作简报分类为 Motion-led / Source-led / Data-explainer 等承诺类型并校验剪辑运动比例。
- 其他支撑：`clip_embedder.py`、`shot_prompt_builder.py`、`source_media_review.py`、`variation_checker.py`、`verify_scene_pacing.py`、`slideshow_risk.py`、`hyperframes_style_bridge.py`、`media_profiles.py` 分别承担媒体嵌入、分镜提示词构建、素材审查、变体检查、节奏验证、幻灯片风险、HyperFrames 桥接、媒体规格等专项任务。
依赖方向单向向外：各模块通过 `lib.paths` 获取根路径，通过 `lib.pipeline_loader` 读取 manifest，通过 `schemas.*` 做数据校验，不反向依赖上层编排器或工具实现。
